# Security Policy

## Supported versions

Semantic Operator follows Semantic Versioning. Until the project establishes multiple
supported release branches, security fixes target the latest released version and `main`.
Users should run the latest release to receive security fixes.

## Reporting a vulnerability

Thank you for reporting vulnerabilities responsibly. Do not disclose a suspected
vulnerability in a public issue, discussion, or pull request.

Report vulnerabilities privately through one of these channels:

- [GitHub Security Advisories](https://github.com/kubeflow/semantic-operator/security/advisories/new)
- The private Kubeflow Steering Committee mailing list at `ksc@kubeflow.org`

Include the affected version, deployment configuration, reproduction steps, impact, and any
known mitigations. Remove credentials, personal data, and production data from the report.

## Disclosure process

The maintainers will acknowledge the report, validate its impact, coordinate a fix and
release, and agree on public disclosure with the reporter. Security fixes may be kept private
until users have a reasonable opportunity to upgrade.

General support requests belong in GitHub issues or the
[Kubeflow community channels](https://www.kubeflow.org/docs/about/community/). Do not use
public community channels for vulnerability reports.
